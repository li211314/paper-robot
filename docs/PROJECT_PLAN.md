# 小纸壳机器人 ESP-IDF C 工程整体方案

- 文档日期：2026-11-06
- 目标工程：`F:\esp\projects\cardboard_robot`
- 目标芯片：ESP32-C3 SuperMini
- 开发框架：ESP-IDF v6.1
- 开发语言：C
- 当前阶段：方案设计，尚未开始编写机器人程序

## 1. 项目目标

参考 B 站作者 Made_by_Z 的“小纸壳机器人”公开视频和社区 Python 复刻工程，实现一个行为一致的 ESP-IDF C 版本。

第一版需要完成以下功能：

1. 开机后在 OLED 上显示机器人表情，并自动眨眼。
2. 左侧或右侧红外模块检测到手时，机器人平滑转向对应方向。
3. 两侧同时检测到手时，回到默认朝向并显示靠近表情。
4. 手离开后保留当前动作约 400ms，再平滑回到默认姿势。
5. 触摸头顶时优先执行低头动作，并显示触摸表情。
6. 触摸结束后继续保留约 1 秒反馈，再恢复普通动作。
7. 所有动作使用平滑加减速，避免舵机突然大幅转动。
8. 所有引脚、方向、脉宽范围和动作速度统一放在配置文件中。

第一版不包含以下功能：

- WiFi 和手机控制
- ROS2 或 USB JSON 控制协议
- 摄像头手部识别
- 语音、音乐和联网功能
- 多套复杂菜单或模式切换

## 2. 硬件基线

按原视频公开画面和社区复刻资料，第一版面向以下硬件：

| 硬件 | 型号或规格 | 数量 |
| --- | --- | --- |
| 主控 | ESP32-C3 SuperMini | 1 |
| 舵机 | SG90 位置型舵机 | 2 |
| 显示屏 | 0.96 寸 SSD1306 OLED，128x64，I2C 地址 0x3C | 1 |
| 触摸模块 | TTP223 电容触摸模块 | 1 |
| 红外模块 | TCRT5000 红外避障或循迹模块 | 2 |
| 电源 | 外部稳压 5V 和 3.3V 电源模块 | 1 |

电源要求：

- 两个 SG90 使用外部稳压 5V 供电，不能直接由 ESP32-C3 的 GPIO 或 3.3V 引脚供电。
- OLED、触摸和红外模块使用 3.3V 供电。
- ESP32、舵机电源和所有模块必须共地。
- 调试时 ESP32 可以通过 USB 供电，但舵机仍应使用外部 5V。
- 接线或改线前先断开外部电源和 USB。

## 3. 默认引脚分配

第一版采用社区复刻工程中已成功使用的一组引脚。所有定义必须集中放在配置头文件中，实物接线不同时只改配置，不改动作逻辑。

| 功能 | ESP32-C3 GPIO | 方向或电平 |
| --- | --- | --- |
| OLED SDA | GPIO0 | I2C 数据 |
| OLED SCL | GPIO1 | I2C 时钟，100kHz |
| 右侧红外 OUT | GPIO3 | 输入，默认低电平有效 |
| 左侧红外 OUT | GPIO4 | 输入，默认低电平有效 |
| 水平转头舵机 | GPIO5 | 50Hz PWM 输出 |
| 俯仰舵机 | GPIO6 | 50Hz PWM 输出 |
| TTP223 触摸 OUT | GPIO10 | 输入，默认高电平有效 |

说明：

- “左”和“右”按面对 OLED 屏幕的方向定义。
- GPIO8 和 GPIO9 是 ESP32-C3 启动相关引脚，应保持空闲。
- 最终接线必须等实物到齐后按模块丝印再次核对。

## 4. 动作设计

### 4.1 默认姿势

- 水平舵机：略向右。
- 俯仰舵机：略微抬头。
- OLED：普通表情，正常状态下每约 3 秒眨眼一次，每次约 180ms。

默认姿势不是舵机理论中位，而是根据机械安装调整后的安全位置。初始值只能用于空载测试，装载纸壳后必须重新校准。

### 4.2 输入到动作的映射

| 输入状态 | 水平动作 | 俯仰动作 | OLED 表情 |
| --- | --- | --- | --- |
| 无检测 | 默认朝向 | 默认抬头 | 普通表情 |
| 仅左侧检测 | 向左转 | 略微抬头 | 靠近表情 |
| 仅右侧检测 | 向右转 | 略微抬头 | 靠近表情 |
| 左右同时检测 | 默认朝向 | 略微抬头 | 靠近表情 |
| 触摸有效 | 默认朝向 | 低头 | 触摸表情 |

优先级从高到低：

1. 触摸
2. 左右红外
3. 普通空闲状态

触摸优先于红外。触摸期间即使红外检测到手，也不执行左右转头。

### 4.3 时间参数

| 参数 | 初值 | 说明 |
| --- | --- | --- |
| 控制循环周期 | 20ms | 同时更新舵机目标和输入状态 |
| 输入防抖时间 | 60ms | 信号持续稳定后才确认状态变化 |
| 手离开回中延时 | 400ms | 避免手短暂抖动导致头部来回晃动 |
| 触摸结束保持时间 | 1000ms | 轻触后也能看清低头反馈 |
| 眨眼间隔 | 3000ms | 仅普通表情下眨眼 |
| 眨眼持续时间 | 180ms | 防止屏幕刷新拖慢控制 |

### 4.4 舵机 PWM

- 频率：50Hz，即周期约 20ms。
- 中位脉宽初值：1500us。
- 第一版安全范围：
  - 水平舵机：1200us 至 1800us。
  - 俯仰舵机：1400us 至 1600us。
- 默认姿势初值：
  - 水平：1560us。
  - 俯仰：1600us。
- 平滑控制：
  - 控制循环每 20ms 最多改变一小段脉宽。
  - 起步时逐渐增加步长。
  - 接近目标时逐渐减小步长。
  - 中途反向时重新缓慢起步。
- SG90 没有角度反馈，软件无法判断机械是否卡住。
- OLED 刷新不得阻塞舵机更新。

以上数值来自参考工程，仅作为首次空载测试值，不得在未检查机械间隙时直接扩大范围。

## 5. 软件架构

### 5.1 数据流

```text
红外 GPIO/触摸 GPIO
        |
        v
输入防抖与触摸保持
        |
        v
行为映射
        |
        +------------------> 目标表情
        |                         |
        |                         v
        |                    OLED 绘制
        |
        +------------------> 目标舵机脉宽
                                  |
                                  v
                           平滑舵机控制
                                  |
                                  v
                          LEDC 50Hz PWM
```

### 5.2 模块划分

| 模块 | 职责 |
| --- | --- |
| `robot_config.h` | 引脚、电平、脉宽范围、速度和时间参数 |
| `input.c/.h` | 初始化 GPIO，读取并防抖左右红外与触摸 |
| `behavior.c/.h` | 输入到动作、表情和目标脉宽的纯逻辑映射 |
| `servo.c/.h` | LEDC PWM 初始化、目标限幅、平滑靠近目标 |
| `ssd1306.c/.h` | OLED I2C 初始化和显存刷新 |
| `display.c/.h` | 普通、眨眼、靠近和触摸表情绘制 |
| `robot_main.c` | 初始化和 20ms 主控制循环 |

模块边界要求：

- `behavior` 不直接访问 GPIO、PWM 或 I2C。
- `servo` 只负责产生安全的 PWM 目标动作。
- `display` 只负责把表情转换成 OLED 像素。
- `robot_main` 负责把输入、行为和输出连接起来。

### 5.3 主循环

主循环每 20ms 执行一次：

1. 读取并更新防抖后的触摸和红外状态。
2. 根据优先级计算目标姿势和目标表情。
3. 向两个舵机模块写入目标。
4. 更新舵机当前脉宽。
5. 在表情发生变化时刷新 OLED。
6. 处理普通表情下的眨眼计时。

主循环不使用长时间 `delay`，因此转头过程中收到新的触摸或红外输入时可以及时改变目标。

## 7. 异常处理与安全

- OLED 未连接或初始化失败：打印错误日志，继续运行舵机和输入功能。
- 舵机 PWM 初始化失败：打印错误日志，保持引脚低电平，不继续输出错误脉宽。
- 非法目标脉宽：在驱动层再次限幅，防止行为模块误传超出范围的值。
- I2C 总线异常：本次刷新失败只记录日志，不影响控制循环。
- 首次上电：默认舵机位置未知，必须卸下头壳或扶住头部进行空载测试。
- 出现异响、堵转、发热或纸壳干涉：立即断开外部电源，不通过扩大 PWM 强行驱动。
- 任何接线调整：先断外部舵机电源，再断 USB。

## 8. 实施步骤

### 阶段 0：板载灯自检（已完成的早期验证）

- 使用 GPIO8 验证 ESP32-C3 SuperMini 可以正常编译、烧录和运行。
- 标准版 Super Mini 的板载用户灯是单色蓝色 LED。
- 板载蓝灯使用 GPIO8，低电平点亮。
- 启动后闪烁 3 次并保持常亮。
- 正式固件已移除分模式自检开关。

### 阶段 1：工程骨架

- 新建独立 ESP-IDF 工程。
- 设置目标芯片为 `esp32c3`。
- 配置最低必要组件。
- 建立统一配置文件和各模块空接口。
- 完成首次编译。

### 阶段 2：基础硬件驱动

- 实现 LEDC 双舵机 PWM。
- 加入 SG90 平滑步进、方向反转重启和脉宽限幅。
- 实现红外和触摸 GPIO 读取与防抖。
- 添加串口日志，打印输入状态和当前目标脉宽。

### 阶段 3：OLED 与表情

- 实现 SSD1306 I2C 初始化和显存刷新。
- 使用 `components/ssd1306` 中的 MIT 许可驱动。
- 固定 SDA=GPIO0、SCL=GPIO1，I2C 地址 0x3C。
- 正常运行时绘制机器人脸，并在空闲状态自动眨眼。
- 绘制普通、眨眼、靠近和触摸表情。
- 验证屏幕缺失时程序仍能继续转头。

### 阶段 4：行为整合

- 移植参考工程的动作优先级和延时逻辑。
- 加入触摸保持、回中延时和自动眨眼。
- 完成完整控制循环。

### 阶段 5：实物调试

- 先单独测试 OLED，再测试红外和触摸。
- 卸下头壳测试两个舵机方向。
- 校准中位、默认姿势和最大安全范围。
- 安装纸壳后再进行小幅度整机测试。

## 12. 假设和待确认项

当前按以下条件设计：

- 主控为 ESP32-C3 SuperMini。
- 板载灯使用 GPIO8 上的单色蓝色用户灯，低电平点亮。
- 商家资料中的 WS2812 示例面向外接灯带，不用于标准版板载蓝灯。
- OLED 为 SSD1306 128x64，I2C 地址 0x3C。
- 两个红外模块使用数字 OUT 输出。
- 触摸模块为 TTP223，触摸时输出高电平。
- 红外检测到手时输出低电平。
- 舵机信号和电源接线正确，所有设备已经共地。

硬件到货后需要确认：

- 红外模块是 3 针还是 4 针，是否带有 AO 模拟输出。
- OLED 的实际 SDA/SCL 引脚。
- 两个舵机的安装方向。
- 默认姿势和最大安全脉宽。
- 电源模块的实际输出电压和接线方式。

如果红外模块只有数字输出，第一版实现左右分区跟随。如果模块带 AO 模拟输出，后续可以在不改变主体架构的前提下增加更连续的手部跟随。
